## 1. Language Modelling

### 1.1 Why Model Language?

Language modelling allows machines to **represent and understand language in a computational way**. A word model captures:
- Meaning, context, and relationships between words
- Enables machines to understand, generate, and analyze human language

### 1.2 Applications of Language Modelling in NLP

**Semantic understanding** — words carry meaning; to comprehend a sentence we must model individual words and their relationships.

**Language generation** — includes machine translation, text summarization, and machine-human dialogue. Word modelling allows relationships between words to be exploited in generating coherent and meaningful sentences.

**Text classification and sentiment analysis** — word representations become features for training ML models that perform sentiment analysis or classification tasks.

**Language understanding** — NLP models must recognize and interpret: named entities, part-of-speech tags, syntactic structures, and sentiment. Word modeling provides representations that capture relevant linguistic features.

## 2. Text Encoding

### 2.1 General Pipeline

```
Raw text
  → Text Standardization
  → Tokenization
  → Vectorization (One-hot / Word Embedding)
  → Input to Deep Networks
```

- **Tokens**: words, characters, or n-grams
- **Tokenization**: process of segmenting text into tokens
- **Vectorization**: transforming tokens into numeric tensors (vectors)

### 2.2 Text Standardization

A form of **feature engineering** that removes encoding differences:
- Convert to **lower case**
- Remove **punctuation**

Benefits: requires less training data; models generalize better.

### 2.3 Tokenization Types

| Type | Description |
|------|-------------|
| **Word tokenization** | Tokens are groups of characters forming words |
| **N-gram tokenization** | Tokens are groups of N consecutive words |
| **Character-level** | Each character is its own token (rarely used) |

### 2.4 One-Hot Encoding

Given a vocabulary of $N$ tokens:
1. Assign a unique integer index $i$ to every token
2. Turn index $i$ into a **binary vector of size $N$**
3. Vector has all zeros except a 1 at the $i$-th position

```python
from tensorflow.keras.preprocessing.text import Tokenizer

samples = ['The cat sat on the mat.', 'The dog ate my homework.']
tokenizer = Tokenizer(num_words=1000)
tokenizer.fit_on_texts(samples)
sequences = tokenizer.texts_to_sequences(samples)  # lists of integers

one_hot_results = tokenizer.texts_to_matrix(samples, mode='binary')
word_index = tokenizer.word_index
print('Found %s unique tokens.' % len(word_index))
```

**Limitations of one-hot encoding:**
- High-dimensional, sparse vectors
- No semantic relationship encoded between words

### 2.5 Word Embedding

Word embedding maps human language into a **geometric space that reflects semantic relationships**.

> Example (Word2Vec): `Cat → Tiger` vector ≈ `Dog → Wolf` vector (both represent "pet → wild")  
> Classic example: `King + Woman - Man = Queen`

**How to obtain word embeddings:**

1. **Learn jointly** with the main task (e.g. document classification): start with random vectors and learn them like neural network weights
2. **Use pre-trained embeddings** learned on a related task

**Popular pre-trained embeddings:**

| Model | Source |
|-------|--------|
| Word2Vec | Google — https://code.google.com/archive/p/word2vec |
| GloVe | Stanford NLP — https://nlp.stanford.edu/projects/glove |
| BERT | Google Research (bidirectional transformer) |
| fastText | Cornell / Caltech / Amazon |
| GPT-2, GPT-3 | OpenAI (Generative Pre-trained Transformer) |

**TensorFlow/Keras Embedding API:**

```python
import tensorflow as tf
import numpy as np

model = tf.keras.Sequential()
model.add(tf.keras.layers.Embedding(
    input_dim=1000,          # vocabulary size
    output_dim=64,           # embedding dimensions
    embeddings_initializer='uniform',
    mask_zero=False,
    input_length=10
))
model.compile('rmsprop', 'mse')

input_array = np.random.randint(1000, size=(32, 10))
output_array = model.predict(input_array)
print(output_array.shape)   # (32, 10, 64)
```

## 3. Neural Machine Translation (NMT)

### 3.1 Task Definition

Given text in one language, **generate a translation** into a different language (e.g. English → French).

### 3.2 Simple Encoder-Decoder Model

```
Input sentence (reversed)
     ↓
  [Encoder RNN]  →  context vector (last hidden state)
                         ↓
                   [Decoder RNN]  →  translated words one at a time
```

**Algorithm flow:**
1. Each word is represented by its vocabulary ID
2. Embedding layer converts IDs to dense vectors (fed into encoder and decoder)
3. Encoder's **last hidden state** is passed to the decoder as context
4. Decoder also receives the correct translation shifted by one time step (`<SOS>` token)
5. At each time step, decoder outputs a score for each word in the output vocabulary
6. **Softmax** converts scores to probabilities; highest probability word is output

**Example:** Input "I drink milk" → reversed to "milk drink I `<pad> <pad> <pad>`" → Decoder outputs "Je bois du lait"

**At inference:** The decoder has **no access to target words**; it is fed its own previous output (starting with `<SOS>`).

### 3.3 Practical Considerations

#### Variable Sentence Length
- Real sentences have different lengths; model assumes constant-length input
- **Solution**: use **padding** (`<pad>` tokens) to create constant-length sequences
- Group sentences into **buckets** (e.g. 1–6, 7–12 words) and pad within each bucket
- Use a **mask** to prevent `<eos>` tokens from contributing to loss

#### Bidirectional RNN
- Conventional RNN treats input text as causal (left-to-right only)
- **Problem**: the word "queen" in different contexts needs future context to encode correctly
- **Solution**: **Bidirectional RNN** — process sequence left-to-right AND right-to-left; concatenate outputs at each time step

#### Large Output Vocabulary
- Softmax over a huge vocabulary is computationally expensive
- **Solution**: **Sampled Softmax** — compute loss using only the correct word and a random sample of incorrect words

## 4. Beam Search

### 4.1 Motivation

Greedy decoding (always picking the highest-probability next word) can lead to suboptimal sequences because an early wrong choice cannot be corrected.

### 4.2 Key Idea

Keep track of the **k most promising partial sentences** at each decoder step.

At each step: extend each of the k sentences by one word and keep only the k most likely results.

- **Parameter $k$**: beam width
- **Trade-off**: larger k → better output quality but more computation (k copies of the model)
- **Limitation**: computationally expensive; does not fully solve the context problem → Attention mechanism is a better solution

## 5. Attention Mechanism

### 5.1 Intuitive Definition

> **Attention is the process of focusing on what is important and fading out what is not important.** *(Chollet, 2021)*

Importance scoring is the starting point of all attention mechanisms. Attention makes features **context-aware**.

**Formal definition:** Attention is a mechanism that dynamically computes the relevance of elements within an input (or between inputs and outputs) by measuring pairwise dependencies, allowing a model to focus on the most informative components when generating a representation.

### 5.2 Why Attention is Important

- Captures **long-range dependencies** in data
- Enables **dynamic weighting** of features/tokens
- Improves **context sensitivity** and model interpretability
- **Replaces** recurrence/convolution in modern architectures (e.g. Transformers)

### 5.3 NMT with Attention

Instead of compressing the entire source sentence into one context vector (the bottleneck problem), attention allows the decoder to look at **all encoder outputs** at every step.

**Algorithm:**
1. At each decoder time step $t$, compute a **weighted sum** of all encoder outputs
2. Weight $\alpha(t, i)$ = importance of the $i$-th encoder output at decoder step $t$
3. Example: if $\alpha(3,2) > \alpha(3,0) > \alpha(3,1)$, the decoder focuses on word "milk" at step 3
4. The block that generates weights is the **alignment model** (Attention layer)

### 5.4 Alignment Model

**Components:**
1. A **time-distributed dense layer** (single neuron) receives all encoder outputs concatenated with the decoder's previous hidden state
2. Outputs a **score (energy)** $e(t,i)$ for each encoder output — measures alignment quality
3. A **softmax** layer converts scores to weights $\alpha(t,i)$ — this is **additive attention** (Bahdanau, 2015)
4. **Multiplicative (Luong) attention**: alignment measured by simple inner (dot) product

### 5.5 Three Alignment Mechanisms

$$\tilde{h}(t) = \sum_i \alpha(t,i)\, y(i)$$

where $\alpha(t,i) = \dfrac{\exp(e(t,i))}{\sum_{i'} \exp(e(t,i'))}$

| Variant | Score $e(t,i)$ |
|---------|----------------|
| **Dot** | $h(t)^T \, y(i)$ |
| **General** | $h(t)^T W \, y(i)$ |
| **Concat (additive)** | $v^T \tanh(W[h(t); y(i)])$ |

## 6. Transformer Architecture

*Based on "Attention is All You Need" — Vaswani et al. (2017)*

### 6.1 High-Level Structure

The Transformer is an **Encoder-Decoder** architecture where **attention replaces recurrence entirely**.

```
Input tokens
    ↓  [Embedding + Positional Encoding]
  Encoder (×N stacked)
    ↓  [encoder output: batch × seq_len × 512]
  Decoder (×N stacked)  ← also receives target tokens (shifted right)
    ↓
  Dense + Softmax
    ↓
Output probabilities over vocabulary
```

### 6.2 Encoder

**Input:** word IDs of shape `[batch_size, max_input_length]`  
**After embedding:** `[batch_size, max_input_length, 512]`  
**Output:** `[batch_size, max_input_length, 512]`

Each encoder layer contains:
1. **Multi-Head Self-Attention** sub-layer
2. **Feed-Forward Network** (two Dense layers: first with ReLU, second with no activation)
3. **Residual (skip) connections** + **Layer Normalization** after each sub-layer

### 6.3 Decoder

**Input 1:** Target sentence shifted right by one step (during training)  
**Input 2:** Encoder output  
**Output:** Probability distribution over vocabulary at each time step — shape `[batch_size, max_output_length, vocab_size]`

**At inference:** No access to target; decoder is fed its own previously generated words, starting with `<SOS>`.

Each decoder layer contains:
1. **Masked Multi-Head Self-Attention** (masks future positions)
2. **Cross Multi-Head Attention** (queries from decoder, keys/values from encoder)
3. **Feed-Forward Network**
4. **Residual connections** + **Layer Normalization** after each sub-layer

### 6.4 Key Properties

- **All layers are time-distributed** → each word is processed independently of others (unlike RNNs)
- Word-word relationships → encoded by **Multi-Head Attention**
- Position within sentence → encoded by **Positional Encoding**
- Basic Encoder-Decoder has **2 embedding layers** and **5 skip connections** (×N with stacking)
- Final decoder output: **Dense layer with Softmax activation**

### 6.5 Positional Encoding

Since Transformer has no recurrence, position information must be injected explicitly.

**Positional embedding:** adds the $i$-th positional embedding to the word embedding of the $i$-th word.

Can be **learned** or computed with a **deterministic formula**:

$$P_{p,2i} = \sin\!\left(\frac{p}{10000^{2i/d}}\right)$$

$$P_{p,2i+1} = \cos\!\left(\frac{p}{10000^{2i/d}}\right)$$

where:
- $p$ = word position in the sequence
- $i$ = index of the embedding dimension
- $d$ = maximum embedding dimension

### 6.6 Scaled Dot-Product Attention

**The core computation unit** of the Transformer.

**Intuition using a dictionary analogy:**

| Concept | Meaning |
|---------|---------|
| **Query (Q)** | What we are looking for |
| **Key (K)** | Labels in the knowledge base (easy to compare against query) |
| **Value (V)** | Actual content we want to retrieve |

**Example:** Encoder encodes "They played chess":

| Token | Part of Speech |
|-------|----------------|
| They  | pronoun (subject) |
| played | verb |
| chess  | noun |

After decoding "They" (a *subject*), decoder queries for a *verb* → finds "played".

**Formula:**

$$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_{\text{keys}}}}\right)\mathbf{V}$$

**Notation:**

| Symbol | Shape | Meaning |
|--------|-------|---------|
| $\mathbf{Q}$ | $m \times d_k$ | $m$ query vectors |
| $\mathbf{K}$ | $n \times d_k$ | $n$ key vectors |
| $\mathbf{V}$ | $n \times d_v$ | $n$ value vectors |
| Output | $m \times d_v$ | One row per query (weighted sum of values) |

**Steps:**
1. Compute similarity between query and all keys via dot product
2. Scale by $\sqrt{d_k}$ to prevent vanishingly small gradients
3. Apply softmax → attention weights sum to 1
4. Compute weighted sum of values → context-aware output vector

**In code (conceptual):**
```python
outputs = sum(values * pairwise_scores(query, keys))
```

### 6.7 Multi-Head Attention

**Key idea:** Run multiple Scaled Dot-Product Attention modules **in parallel**, each in a different subspace, then concatenate.

Different heads capture different aspects: syntax, coreference, positional patterns, etc.

**Architecture:**
1. **Linear projections** of Q, K, V (time-distributed Dense, no activation) into $H$ heads
2. Each head computes Scaled Dot-Product Attention independently
3. **Concatenate** all head outputs
4. Final **linear projection** (Dense) to produce output

**Formula:**

For head $h = 1\ldots H$:
$$\text{head}_h = \text{Attn}\!\left(\mathbf{Q}W_h^Q,\; \mathbf{K}W_h^K,\; \mathbf{V}W_h^V\right)$$

$$\text{MHA}(\mathbf{Q},\mathbf{K},\mathbf{V}) = [\text{head}_1;\ldots;\text{head}_H]\,W^O$$

## 7. Varieties of Attention

*(From supplementary notes)*

### Notation Reference

| Symbol | Meaning | Shape |
|--------|---------|-------|
| $n$ | length of key/value sequence | — |
| $m$ | length of query sequence | — |
| $d_k$ | key & query dimensionality | — |
| $d_v$ | value dimensionality | — |
| $\mathbf{Q}$ | stacked query vectors | $m \times d_k$ |
| $\mathbf{K}$ | stacked key vectors | $n \times d_k$ |
| $\mathbf{V}$ | stacked value vectors | $n \times d_v$ |

### Variety 1: Additive vs. Scaled Dot-Product

| Variant | Score $e_{ij}$ | Output $o_i$ |
|---------|----------------|--------------|
| **Additive** (Bahdanau 2015) | $\mathbf{v}_a^\top \tanh(\mathbf{W}_q\mathbf{q}_i + \mathbf{W}_k\mathbf{k}_j + \mathbf{b}_a)$ | $\sum_j \alpha_{ij}\mathbf{v}_j$ |
| **Scaled dot-product** (Vaswani 2017) | $\mathbf{q}_i^\top\mathbf{k}_j / \sqrt{d_k}$ | same $\alpha_{ij}$, same $o_i$ |

> **Hint:** Additive uses an MLP (has learnable parameters in score function); dot-product is parameter-free after input projections and is GPU-friendly.

### Variety 2: Self-Attention vs. Cross-Attention

| Type | Q, K, V source | Use case |
|------|---------------|----------|
| **Self-attention** | All from the **same** sequence | BERT, ViT — tokens mutually contextualise |
| **Cross-attention** | Q from decoder, K/V from encoder | Encoder-Decoder MT, text-to-image diffusion (UNet queries CLIP text) |

**Self-attention formulation:**
$$Q = XW^Q,\quad K = XW^K,\quad V = XW^V \quad (X = \text{input sequence})$$

### Variety 3: Soft vs. Hard Attention

| Type | Mechanism | Training |
|------|-----------|----------|
| **Soft (deterministic)** | $\alpha_{ij} = \text{softmax}_j(e_{ij})$ — differentiable | Standard backprop |
| **Hard (stochastic)** | $j^* \sim \text{Cat}(\text{softmax}_j(e_{ij}))$; $o_i = v_{j^*}$ | REINFORCE / Gumbel-Softmax |

> **Note:** Hard attention gives sparse, human-interpretable glimpses but higher gradient variance. Classic example: *Show, Attend and Tell* (image captioning).

### Variety 4: Local / Windowed vs. Global Attention

**Local attention** masks scores outside a window of size $w$:
- Memory: $O(mw)$ vs $O(mn)$ for global
- **Used in:** Longformer, Wav2Vec 2.0

**Global attention** attends to all positions — standard Transformer behavior.

### Variety 5: Multi-Head Attention

*(Already detailed in Section 6.7)*

> **Hint:** Different heads capture syntax, coreference, positional patterns, etc.

### Variety 6: Hierarchical & Multi-Scale Attention

Build attention at multiple granularities: token → sentence → document.

| Model | Task |
|-------|------|
| **Hierarchical Attention Network** (Yang 2016) | Long-document classification |
| **Swin Transformer** | Shifted windows for images (multi-scale vision) |

> **Design tip:** Combine with pooling to keep compute bounded while capturing global context.

### Variety 7: Sparse / Efficient / Linear Attention

**Problem:** Standard attention is $O(n^2)$ in sequence length.

| Method | Approach | Complexity |
|--------|----------|------------|
| **Performer** (linear kernel trick) | Approximates softmax with random features $\phi$: $\text{Attn} \approx \phi(\mathbf{Q})[\phi(\mathbf{K})^\top\mathbf{V}] / \phi(\mathbf{Q})\phi(\mathbf{K})^\top\mathbf{1}$ | $O(m+n)$ |
| **Sparse Transformer** | Block, strided, or dilated attention patterns | $O(n\sqrt{n})$ |
| **Longformer** | Local window + global tokens | $O(n)$ |
| **FlashAttention-2** | Exact softmax, tiled GPU kernels | $O(1)$ extra memory |

### Variety 8: Monotonic / Align-to-Time Attention

Enforces left-to-right, streaming constraint:

$$\alpha_{ij} = 0 \quad \text{for } j < i - (l-1)$$

where $l$ is the lookback window.

- **MILk** (Monotonic Infinite Lookback) and RNNT alignments enable **online ASR** (speech recognition)
- Reduces latency; guarantees causality

### Variety 9: Modal-Specific Extensions

| Domain | Special Twist | Example |
|--------|--------------|---------|
| **Vision** | 2D relative positions, shifted windows | Swin Transformer, ViT-Hybrid |
| **Graphs** | Attention on node pairs + edge types | Graph Attention Network (GAT) |
| **Point Cloud** | 3D coordinate-conditioned attention | Point Transformer |

## Architecture Comparison

| Feature | Vanilla RNN | Encoder-Decoder RNN | Transformer |
|---------|-------------|---------------------|-------------|
| Handles long-range deps. | Poor | Limited (bottleneck) | Excellent |
| Parallelizable | No | No | Yes |
| Positional info | Implicit (sequential) | Implicit | Explicit (positional encoding) |
| Context mechanism | Hidden state | Fixed context vector | Multi-Head Attention |
| Scalability | $O(n)$ sequential | $O(n)$ | $O(n^2)$ (softmax) / $O(n)$ (efficient) |
