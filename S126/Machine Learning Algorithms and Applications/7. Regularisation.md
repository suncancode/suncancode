# Regularization

---

## 1. Machine Learning Tasks (Revisited)

A **task** describes how a machine learning system should process an example. An **example** is a collection of *features* quantitatively measured from an object or event, represented as a vector $\mathbf{x} \in \mathbb{R}^n$.

### Classification
Assign an input to one of $k$ categories. The system learns a function:

$$f : \mathbb{R}^n \to \{1, \dots, k\}$$

where $y = f(\mathbf{x})$ assigns feature vector $\mathbf{x}$ to category $y$. The function may instead output a probability distribution over the classes.

### Regression
Predict a numerical value given an input — i.e., $f : \mathbb{R}^n \to \mathbb{R}$. This contrasts with classification, where the output is a categorical data type.

### Transcription
Observe a relatively unstructured representation of data and transcribe it into discrete textual form, e.g. $f : \mathbb{R}^n \to \mathcal{A}^{k(m)}$, where $\mathcal{A}$ is a language alphabet (English, Yoruba, etc.) and $k(m)$ is a variable length depending on the application. **Speech recognition** is an example.

### Machine Translation
Convert a sequence of symbols in one language to a sequence in another, e.g. $f : \mathcal{A}_x^{k(m)} \to \mathcal{A}_y^{k(m)}$, where $\mathcal{A}_x$ is the source-language alphabet (English, Punjabi, Urdu, Mandarin, Yoruba, …) and $\mathcal{A}_y$ is the target-language alphabet (German, French, Russian, …).

### Tasks as Learning of Concepts
- We usually do **not** know a compact analytical function that achieves the mapping underlying a concept.
- Instead, imagine a set of candidate functions — the **hypothesis space** $\mathcal{H}$.
- The goal is to find $h \in \mathcal{H}$ that minimises the error in **generalising** the concept to unseen samples.
- A neural network is a **universal approximator** and serves as a "template" for the function to be learned.
- A neural network is a **parameterised function** $f_w$ whose parameters (weights, biases, etc.) are learned from data — this process is called **training**.

$$f_w : x \mapsto y, \qquad w \in W \ \text{(parameters / weights)}$$

We must learn the parameters that yield a model which **generalizes** knowledge of the concept.

## 2. Regularization

### The Learning Problem
Training a network means finding the parameters $w^* \in W$ that minimise a loss function $L : W \to \mathbb{R}$:

$$w^* = \arg\min_{w \in W} L(w)$$

The loss is generally written as an **expected risk** combining a fidelity term and a penalty:

$$L = \mathbb{E}\big[\, E(x, t) + R(\cdot)\,\big]$$

where:
- $E(x, t)$ is the **error function** (fidelity term), a function of input $x$ and target $t$.
- $R(\cdot)$ is the **regularization term** — a penalty on the model that constrains the set of parameters from which we select.

In practice, the **empirical risk** $\hat{L}$ approximates the expected risk to obtain the optimal weights.

> **Definition (Kukačka et al., 2017):** Any supplementary technique aimed at making a model generalize better is a form of regularization.

### Five Elements Responsible for the Learned Weights $w^*$
1. **$D$** — the training set
2. **$f$** — the selected model family (hypothesis space $\mathcal{H}$)
3. **$E$** — the chosen error function
4. **$R$** — the regularization term
5. The **optimization technique** used to find the optimum $w$

Each of these five elements is a lever through which regularization can be applied, giving the taxonomy below.

---

### 2.1 Regularization via Data
Transform a given dataset $D$ into a new, contextually appropriate dataset $D_R$.

- **Feature extraction:** PCA, KPCA, Fourier transform, wavelet transform, autoencoders, word models, etc.
- **Preprocessing**, **feature-space transformation**, **distribution remodelling**.
- **Data generation:** augmented datasets.
- Both transformation and augmentation can use **stochastic (probabilistic) parameters**.

A stochastic transformation may take the form:

$$\tau_\theta(x) = x + \theta, \qquad \theta \sim \mathcal{N}(\mathbf{0}, \mathbf{\Sigma})$$

The parameter $\theta$ can be generated in three ways:
1. **Deterministically** (fixed by an equation)
2. **Randomly**, according to some distribution
3. **Adaptively**, obtained through optimization (constrained, unconstrained, or stochastic) with a specific objective.

The transformation can be:
- **Representation-preserving** — keeps both feature space and distribution.
- **Representation-modifying** — possibly different distribution/feature space; maps the original factors to a space where learning is easier.

Transformations can occur in different spaces/formats:
- **Input space** — apply transformation to data $x$.
- **Hidden-feature space** — e.g. modifying layer outputs.
- **Target (label)** — modified during training.

They can be applied during **training** (training samples) or **testing** (test samples).

---

### 2.2 Regularization via Network Architecture
- Merely **selecting an architecture** is regularization, because it prescribes the type of function used for approximation. *"...using deep architectures does indeed express a useful prior over the space of functions the model learns"* (Goodfellow et al., 2016, p.200).
- The network maps input to output according to its number of layers and neurons, already constraining the type of mapping.
- The **weight structure** imposed by the architecture interacts with the optimization technique to shape the search space (we traverse an error surface that is a function of the weights).
- Certain **invariances are "baked in"** — e.g. convolution. (Table 3 of Kukačka et al., 2017 lists such methods and their encoded assumptions.)

**Weight sharing:** reuses a trainable parameter across several parts of the network.
- Reduces model complexity.
- Encodes prior knowledge about the data-generating process (convolution → shift-equivariance and locality of feature extraction).

**Activation functions:** the choice matters because of how it shapes a neuron's output.
- **ReLU** ameliorates the vanishing-gradient problem.
- **Dropout** and **Maxout** allow approximating the geometric mean of an ensemble's predictions at test time.
- **GeLU** combines stochastic regularizers (such as dropout) with non-linearities (activation functions).

---

### 2.3 Regularization via the Error Function
- Error functions usually measure the quality of the network's approximation (mean-squared error, cross-entropy, etc.).
- The **Dice coefficient**, when used as an error function, helps combat **data imbalance**. Common as a segmentation metric, it has been adapted into a loss:

$$DSC = \frac{2\,|X \cap Y|}{|X| + |Y|}$$

where $|X|$ is the number of correctly segmented pixels and $|Y|$ the number of incorrectly segmented pixels.

TensorFlow implementation:

```python
def DiceLoss(targets, inputs, smooth=1e-6):
    # flatten label and prediction tensors
    inputs = K.flatten(inputs)
    targets = K.flatten(targets)
    intersection = K.sum(K.dot(targets, inputs))
    dice = (2 * intersection + smooth) / (K.sum(targets) + K.sum(inputs) + smooth)
    return 1 - dice
```

### 2.4 Regularization via the Regularization Term
- The obvious approach: **add a regularizer** to the loss function.
- This regularizer usually does **not** involve the target; it is a penalty on, e.g., the weights:
  - **Ridge regression:** $\|w\|_2^2$
  - **LASSO:** $\|w\|_1$
- **Weight decay** is another regularizer, controlled by $\lambda$, which balances the regularization against the fidelity term and promotes error reduction on the training set.

**Smoothness constraint:** specifies the "landscape" of the learned mapping. If two inputs $x_1$ and $x_2$ are close, their outputs $f_w(x_1)$ and $f_w(x_2)$ should also be close. It is formulated using the **Frobenius norm of the Jacobian**:

$$R = \big\| J_{f_w}(x) \big\|_F$$

where $J_{f_w}(x)$ is the Jacobian of the input–output mapping $f_w$ for fixed weights $w$.

- This penalises mappings with **large derivatives** (no big output changes) — cf. the **contractive autoencoder**.
- The Frobenius norm of a matrix $M \in \mathbb{R}^{n \times m}$ is:

$$\|M\|_F = \sqrt{\sum_{i,j} |m_{ij}|^2}$$

i.e. the square root of the sum of the squared magnitudes of its elements.

- This appears in the Contractive Autoencoder regularizer: $\Omega(\mathbf{h}) = \left\| \frac{\partial f(\mathbf{x})}{\partial \mathbf{x}} \right\|_F^2$.

### 2.5 Regularization via Optimization
**Stochastic Gradient Descent (SGD)** is the most frequently used optimizer in deep learning. Basic weight update:

$$w_{t+1} = w_t - \eta_t \nabla_w L(w_t, d_t)$$

where $\nabla_w L(w_t, d_t)$ is the gradient of the loss evaluated on a mini-batch $d_t$. Extensions include **Adam, RMSProp, AdaGrad**, etc.

Optimization involves three phases — **(i) initialization, (ii) update, (iii) termination** — and regularization can act through each.

#### (i) Initialization
- Sample initial weights from a distribution, keeping the **variance of activations near 1** across layers to avoid vanishing/exploding activations and gradients.
- Optionally **prime learning by pre-training** on data from a different task in the same domain.
- Example: Transformer-based language models such as OpenAI's **GPT** series are pre-trained on large corpora (web documents, books), then **fine-tuned** on specific NLP tasks (classification, question-answering, text generation), exhibiting strong language understanding.
- Initialization can be **with or without pre-training**:
  - *Without pre-training:* (i) random initialization, (ii) orthogonal weight matrices, (iii) data-dependent initialization.
  - *With pre-training:* (i) greedy layer-wise pre-training, (ii) curriculum learning, (iii) spatial contrasting, (iv) subtask splitting.

#### (ii) Update
- **Update rules:** momentum, learning-rate schedules, online batch selection, SGD alternatives (L-BFGS, Hessian-free methods, etc.).
- **Gradient and weight filters:**
  - **Dropout** — stochastically zeroing out activations.
  - **Annealed Langevin noise** — adding noise to the gradient.
  - **AnnealSGD** — annealing the learning rate (exponential, linear, or step decay) for better exploration of the parameter space and improved convergence.

#### (iii) Termination
Stopping at the right moment improves generalization by reducing the discrepancy between minimizers of the **expected** and **empirical** risk. A validation set can determine the stopping point.
- **With a validation set:** (i) early stopping, (ii) choice of validation set.
- **Without a validation set:** (i) fixed number of iterations, (ii) optimized approximation algorithm.

TensorFlow early stopping:

```python
callback = tf.keras.callbacks.EarlyStopping(monitor='loss', patience=3)
# Stops training when the loss does not improve for three consecutive epochs.

model = tf.keras.models.Sequential([tf.keras.layers.Dense(10)])
model.compile(tf.keras.optimizers.SGD(), loss='mse')

history = model.fit(np.arange(100).reshape(5, 20), np.zeros(5),
                    epochs=10, batch_size=1, callbacks=[callback], verbose=0)
len(history.history['loss'])  # Only 4 epochs are run.
```

## Summary: The Regularization Taxonomy
Regularization can be introduced through any of the five elements that determine $w^*$:

| Element | Regularization approach |
|---|---|
| Data ($D$) | Feature extraction, preprocessing, augmentation, stochastic transforms |
| Model ($f$) | Architecture choice, weight sharing, activation functions |
| Error function ($E$) | Dice loss and other generalization-promoting losses |
| Regularization term ($R$) | Ridge ($L_2$), LASSO ($L_1$), weight decay, smoothness/Jacobian penalty |
| Optimization | Initialization, update filters (dropout, noise), early stopping |
